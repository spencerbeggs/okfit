# Decision

* [A body digest inside generated detects real drift, not a rewritten date](profiles-body-sha256-detects-real-drift.md) - generated.body_sha256, a lowercase hex sha256 of the P-6-normalized body, lets generated-at-drift compare content instead of dates, so a squash or rebase merge no longer looks like drift.
* [A cited file that other checkouts cannot see is a lint, split by whether it is ignored](untracked-resources.md) - validate flags a resource or sources\[\].resource that exists locally but is gitignored (resource-ignored, error) or not yet tracked (resource-untracked, warn), as an engine lint that --skip-provenance and the language server skip.
* [A concept outside the repository is a typed failure](concept-outside-repository-is-a-typed-failure.md) - Derivation.generatedAt fails with ConceptOutsideRepositoryError when a concept file resolves outside the repository, rather than reporting a provenance reason or a git error.
* [A deprecated concept's replacement is followed](superseded-by-is-followed.md) - superseded_by is a path field, two core lints check it, Graph.replacement walks the chain to the first current concept, and the query layer exposes it as a current filter and a replacement; okfit context does not follow it and the profile declares no field for it.
* [A non-empty actors list is an allow-list and okfit never stores emails](actor-allow-list.md) - A non-empty \[actors\].humans list gates who may verify, matched by id or glob without emails, and okfit.actor in git config names the explicit id.
* [A shared @okfit/engine package replaces cli-as-copy-contract](engine-front-end-split.md) - The platform layer, config discovery, and the validate/verify/sync/init/context programs moved into a new @okfit/engine package that both @okfit/cli and @okfit/mcp depend on directly, replacing an auto-installed peer-dependency arrangement that could never produce a runnable bin.
* [A verification is bound to the content it covered](verification-binds-content.md) - okfit verify records a digest of the body plus authored frontmatter beside the verified entry, so a later edit is detectable as drift while the spec's trust tier stays unchanged.
* [A walk past maxDepth fails typed, never silently truncates](walk-depth-cap.md) - Bundle.load fails with a typed BundleDepthExceededError when the walk descends past maxDepth, rather than silently truncating the walk at the cap.
* [An unknown status is not current knowledge](unknown-status-is-not-current.md) - A status outside draft, stable and deprecated is kept and shown as unknown, never read as stable; every surface excludes it from current knowledge and okfit verify refuses to attest it, except when the same write sets the status.
* [Bundle, Graph, Derive, and Validate are static facades, not services](core-static-facades.md) - Bundle, Graph, Derive, and Validate are static facades (private-constructor classes with static members) rather than Effect services, because their operations are pure or depend only on FileSystem and Path.
* [Concept files are named for their topic; ids stay paths](topical-concept-names.md) - A concept file is named for its stable topic in two to four words and the claim lives in title and description; ids remain bundle-relative paths and okfit mv makes a rename cheap.
* [Config discovery is assembled through AppConfig.layer, not a hand-rolled resolver chain](config-discovery.md) - The CLI resolves project config through @effected/app's AppConfig.layer, varying only its resolvers/xdg/systemEtc options per branch, rather than building ConfigFile.layer directly with a hand-rolled projectResolver.
* [Every okfit digest lives in one integrity family, outside the spec's families](integrity-family.md) - okfit stores its digests only under a top-level integrity key, so generated and verified stay exactly as OKF v0.2 defines them and a digest is 16 hex characters of SHA-256.
* [Exactly one Project concept, at the bundle root](one-project-at-root.md) - The software-project profile requires exactly one Project concept and requires it to live at the bundle root, enforced as three non-configurable profile errors.
* [Exit codes are a fixed six-value total order](cli-exit-codes.md) - okfit's exit codes form one fixed, non-configurable total order from 0 to 130, where warnings and info never change the result.
* [Frontmatter splices are a shared engine surface for the CLI's verify and the language server's actions](frontmatter-edits.md) - @okfit/engine's edits/FrontmatterEdits.ts exposes the verify/locate.ts and verify/splice.ts splice machinery as a public, Context-free facade so @okfit/lsp's code actions and commands can compute the same byte-range edits okfit verify performs, instead of the splice modules staying CLI-private.
* [Generated.at is the author date of the last commit that changed the body](generated-at-source.md) - generated.at is computed as the author date of the newest commit whose blob changed the concept's body, never the stamp commit's date.
* [Heading anchors match github-slugger, through the kit's slugger](heading-slugs.md) - The broken-links fragment check resolves against @effected/markdown's headingSlugs, which ports github-slugger, rather than okfit's own slug rule, accepting that links written to the old rule start warning.
* [Human actor ids resolve through a five-step fallback order](profiles-human-actor-resolution.md) - A human actor id resolves through a five-step, first-hit-wins fallback order that prefers an explicit git config id, then a configured spelling, over an auto-derived one.
* [Interactive prompts are gated by audience and terminal, and the audience never refuses a command](interactive-prompt-gates.md) - okfit prompts only when the audience is human and stdin and stdout are terminals; --audience, --human, --agent, --ci and OKFIT_AUDIENCE shape output and prompting but never make a command fail.
* [Loading never fails a concept for a bad family](content-tolerant-loading.md) - Bundle.load never rejects a concept outright for a malformed optional field; a bad family is reported as a lint diagnostic while the rest of the concept still loads.
* [Markdown that is not a concept is skipped, not an error](non-concept-markdown-is-skipped.md) - A .md file with no frontmatter, or frontmatter with no type, is not a concept under OKF v0.3 §3.2; core skips it with a warning, and a symlink that leaves the bundle is never loaded.
* [One engine query layer serves the MCP tools, the CLI and the verify picker](engine-concept-query-layer.md) - @okfit/engine's ConceptQuery is the single read-only query layer under the MCP concept tools, okfit query, and the future interactive okfit verify picker; there is no okfit status command.
* [Repository resources are classified by where they resolve](repository-resources.md) - A cited resource inside the bundle follows OKF v0.3 §6, one inside the project root is a repository resource okfit may stat, list and ask git about, and one outside the project root is never touched and is reported as resource-outside-project from the written value alone.
* [The MCP server is Effect-native and lists the stateless 2026-07-28 adapter first](mcp-protocol-versions.md) - The okfit-mcp server stays on effect/ai/McpServer and declares three protocol adapters, the stateless 2026-07-28 revision first and the two stateful ones behind it, with an agent-facing instructions string surfaced on both initialize and server/discover.
* [The MCP server is Effect-native and speaks the legacy protocol era](mcp-effect-native-legacy-era.md) - The okfit-mcp server is built on effect/unstable/ai/McpServer rather than the MCP TypeScript SDK, and negotiates the 2025-11-25 protocol era rather than the newest published one.
* [The PostToolUse hook keeps only conformance blocking and the generated.by check, once the language server delivers lint and profile findings](posttooluse-hook-scope.md) - LSP phase 4 shrinks the Claude Code plugin's PostToolUse hook to two jobs, blocking on a core.conformance diagnostic and the Write-time generated.by check, because the registered language server now delivers core.lint and profile findings with precise ranges directly in the editor.
* [The VS Code extension lives at vscode/, not under plugins/ or packages/](vscode-extension-location.md) - @okfit/vscode-extension lives at the workspace root under vscode/, sibling to packages/\* and plugin/, rather than under either directory.
* [The carrier keeps its front ends' bin names, proven under allowSharedBins](plugin-shared-bins.md) - @okfit/plugin declares okfit, okfit-mcp and okfit-lsp although @okfit/cli, @okfit/mcp and @okfit/lsp declare the same names, and the packed-install e2e passes allowSharedBins and proves the carrier's own shims instead of moving to carrier-only bins.
* [The declared OKF version gates the v0.2 fallbacks](declared-okf-version-gates-fallbacks.md) - A bundle's root index.md okf_version decides, through one gate in core, whether bare paths may fall back to the bundle root and how a computation is located; a bundle that declares 0.3 or later gets the strict v0.3 rules.
* [The engine version, not the producer version, is what a report is compared on](comparable-version.md) - Every JSON envelope stamps engine_version from @okfit/engine itself and carries the meta-package it was installed through as distribution, and core owns the config schema version, because okfit_version only ever named the producing front end and two front ends over one engine read as drift.
* [The language and MCP servers survive a stray crash once serving, and exit on one before](server-crash-survival.md) - okfit-lsp and okfit-mcp run under the kit's crash guards with the exitBeforeConnect policy for both uncaught exceptions and unhandled rejections: a stray error before the server is serving exits 1, and once serving it is logged on stderr and the server keeps answering.
* [The language server runs the reference vscode-languageserver library behind an Effect transport seam](lsp-reference-transport.md) - @okfit/lsp wraps the reference vscode-languageserver library behind an eight-member LspTransportShape rather than writing an Effect-native LSP transport or adopting an MCP-TypeScript-SDK-style route, so a later transport can replace it without touching a feature.
* [The plugin declares a minimum CLI version and the context envelope reports the CLI's](plugin-declares-minimum-cli.md) - plugin/ owns an explicit MIN_CLI_VERSION floor, injected into the hook library, and okfit context --format json carries cli_version, so the SessionStart hook can tell a project to update an older CLI; the floor moves only when a hook or skill needs a newer CLI feature.
* [The root index's metadata is read and kept](root-index-metadata-is-kept.md) - Core reads title, description, license, okf_version and extension keys from the bundle-root index.md (OKF v0.3 §8.1), and sync re-emits the existing frontmatter bytes instead of rewriting the block.
* [The software-project vocabulary grows a fourth time from open migration findings](profiles-vocabulary-round-four.md) - Two types (Flow, Fixture), one tag (config), and a broadened compat tag were added to the software-project profile because migrations kept filing cross-module sequences, external stand-ins, config concerns, and host portability with no home.
* [The software-project vocabulary grows a second time from the effected and tsdoctor migrations](profiles-vocabulary-round-two.md) - Three types (Consumer, Roadmap, Measurement) and three tags (bundle, observability, deps) were added to the software-project profile because two further migrations had to add the same repo-local extensions to express downstream scope, queued work, and empirical evidence.
* [The software-project vocabulary grows a third time from the silk action migrations](profiles-vocabulary-round-three.md) - Two types (Invariant, Incident), a worker Module kind, and two tags (github, docs) were added to the software-project profile, and Gotcha and Roadmap guidance now settle the known-bug and no-in-repo-resource cases, because four GitHub Action migrations filed the same gaps.
* [The software-project vocabulary grows from what migrations could not express](vocabulary-growth.md) - Five types (Runbook, Glossary, Limitation, DataModel, Gotcha), three tags (dx, ci, compat), and structured Module and Interface fields were added to the software-project profile because three real migrations had to contort the same kinds of knowledge into the original six types.
* [The validate hook fires PostToolUse, not PreToolUse](plugin-posttooluse-not-pretooluse.md) - The Claude Code plugin's validate hook fires on PostToolUse, not the spec's PreToolUse, because the CLI can only validate bytes that already exist on disk.
* [Time is an explicit argument, never a Clock service](core-time-as-argument.md) - Core takes now as an explicit DateTime.Utc argument everywhere staleness matters, and never depends on an Effect Clock service.
* [Tool packages pin the kit exactly; libraries keep carets and peers](tool-kit-ranges.md) - @okfit/cli, @okfit/mcp, @okfit/lsp and @okfit/engine write every effect, @effect/\* and @effected/\* runtime dependency as catalog:effected:exact, so an installed okfit owns the kit it was tested with; @okfit/core and @okfit/profiles stay libraries with caret peers.
* [Uncommitted provenance is the caller's to interpret](uncommitted-provenance.md) - Derivation reports an uncommitted body's provenance without ever substituting the current time, leaving the interpretation to the caller.
* [User docs live under /docs; package hierarchies live at the site root beside their generated API](website-package-pages.md) - The okfit site serves user-facing docs under /docs and a technical page hierarchy per package at /\<pkg>, next to that package's generated /\<pkg>/api, rather than nesting packages under /docs or using one flat tree.
* [Verification drift is a signal to weigh, never a gate](drift-is-a-signal.md) - The verified-drift lint defaults to warn and no default config makes an edit fail CI; users who want enforcement raise the lint level or add their own hooks.
* [okfit sync --staged stamps the git index with now, the one place a wall-clock stamp is honest](sync-staged-stamps.md) - Inside a pre-commit hook the current instant is the commit's author date to within seconds, so --staged stamps staged concepts with now and their digest; the default sync still never substitutes now.
* [okfit sync is the one command that regenerates every derived-content family](sync-command-scope.md) - okfit sync computes generated.at, index.md, and log.md in one command with three selectable modes, agent-runnable and never touching verified.
* [okfit sync's log mode appends into the newest logged day and dedupes on its own spellings](sync-log-days.md) - Log mode adds items for every committed concept dated on or after the newest logged date, appending into that day's existing group when no mechanical item already names the concept; --since widens the floor on request.
* [okfit's front ends build on @effected/{engine,cli,mcp} rather than hand-rolled equivalents](effected-kit-adoption.md) - @okfit/cli, @okfit/mcp, @okfit/engine and the workspace's own boundary tests now depend on effected's front-end kit -- @effected/kit, @effected/cli-kit, @effected/mcp-kit, and @effected/workspaces -- in place of copies this repository hand-rolled and maintained itself.
* [stale --verify rolls stale_after forward, and plain verify never does](stale-verify.md) - okfit stale --verify re-attests the chosen stale concepts and moves their stale_after to the attestation instant plus lifecycle.default_stale_after in one all-or-nothing write; verify itself leaves stale_after alone.
