# Agent plugin hooks contract

## Two hooks

`SessionStart` (`hooks/session-start/orientation.sh`, no matcher — every
source, `startup`/`resume`/`clear`/`compact`, re-orients) and `PostToolUse`
(`hooks/post-tool-use/validate.sh`, matcher `Write|Edit`), declared in
`plugin/pluginfinity.config.ts:11-14` (SessionStart timeout 10, PostToolUse
timeout 30) -- the contract is unchanged from the old hand-written
`hooks.json`, but each host's hooks file is now generated by
`pluginfinity build` and the scripts run on the pluginfinity hook library
(`plugin/README.md:77,88`, `plugin/CLAUDE.md:64-67,78-86`).

## SessionStart contract

Calls `okfit context --trust --format json` once, never `okfit validate`;
`--trust` adds one bundle load for the trust counts, where plain `context`
never loads the bundle. When drifted plus stale concepts total more than
zero, the hook prints a trust line right after the config line, naming the
first three drifted ids and, only when something drifted, the drift legend. On any
failure of the `--trust` call (an older CLI that rejects the flag) it
retries plain `okfit context --format json` and prints no trust line. Turns the
result into `additionalContext`: bundle root and profile, the full
vocabulary, the bundle's `index.md` contents (truncated at 12,000 bytes),
and a nudge when `actors.agent` is unset. With no config at all it still
shows the default profile's vocabulary plus a note that `okfit init` would
scaffold one (`plugin/README.md:77-87`, `plugin/CLAUDE.md:56-62`).

## PostToolUse contract

The write has already landed by the time this hook runs, so it is a
stop-and-fix signal, never a prevention. As of LSP phase 4, [The
PostToolUse hook keeps only conformance blocking and the generated.by
check, once the language server delivers lint and profile
findings](../decisions/posttooluse-hook-scope.md)
the hook keeps exactly two jobs, now that the registered language server
delivers `core.lint` and profile findings with precise ranges directly in
the editor. For a path under the bundle root, it runs
`okfit validate --root <project_root> <file> --format json --skip-provenance`
(the bundle loads whole; the edited file as a target scopes the reported
diagnostics to it), and turns a
`core.conformance` hit into `{"decision": "block", ...}`; every other
diagnostic for that file — `core.lint`, profile findings — is silent
here and no longer emitted as `additionalContext`. One check reads the
written file itself: when the config sets `actors.agent`, a concept file
(never `index.md` or `log.md`) whose frontmatter has no `generated.by`
blocks on `Write` and warns on `Edit`, with the exact `by:` value to add
in the message ([#74](https://github.com/spencerbeggs/okfit/issues/74):
the okf-authoring rule alone reached 109 of 268 concepts under one
brief, and this hook is the one place that knows the write came from the
agent). A path outside the bundle root never reaches `okfit validate` at
all (`plugin/README.md:88-112`, `plugin/CLAUDE.md:64-76`). On Copilot, which
honours no `PostToolUse` block, the same reason is sent as
`additionalContext` (`plugin/CLAUDE.md:72-74`). The drift lint costs a git walk
per concept; measured on this bundle it took validate from about 0.5 s to
1.7 s, so the edit-time hook skips it — the lint still runs in CI and
through the MCP `validate_bundle` tool. The hook never blocks on
`verified-drift`: an agent may edit a verified concept, the edit shows as
drift, and re-verifying stays a human act (see [Verification drift is a
signal to weigh, never a gate](../decisions/drift-is-a-signal.md)).

## Kill switches and CLI resolution

`OKFIT_HOOKS=off` disables both hooks; `OKFIT_SESSION_HOOK=off` and
`OKFIT_VALIDATE_HOOK=off` disable one each, comparison exact-string `off`
only. Both hooks resolve the CLI the same way: `$OKFIT_CLI_CMD` →
`<project>/node_modules/.bin/okfit` → `okfit` on `PATH`. If none resolves,
the session hook prints a nudge and the validate hook allows the write
silently; neither hook ever runs `npx` or exits non-zero
(`plugin/README.md:113-127`, `plugin/CLAUDE.md:47-54`). Any non-zero exit
fails open and is logged under `$XDG_STATE_HOME/pluginfinity/okfit/`.

## MCP loader status

`pluginfinity.config.ts` registers `mcpServers.mcp`, running
`{"command": "sh", "args": ["${PLUGIN_ROOT}/bin/start-mcp.sh"]}` (the
build writes it inline into the Claude `plugin.json` and into the Copilot
`mcp.json`);
the loader exports `OKFIT_PROJECT_DIR` before resolving the project's own
`node_modules/.bin/okfit-mcp`, falling back to `npx --yes @okfit/mcp`. The
`okf-docs` agent's `tools:` block allowlists the six served tool names
verbatim (`mcp__plugin_okfit_mcp__describe_vocabulary` on Claude Code, `mcp/<tool>` on
Copilot,
`list_concepts`, `get_concept`, `concept_neighbors`, `stale_report`,
`validate_bundle`) — see `okf/interfaces/okfit-mcp.md` for the tool
contract itself.
